# Marlowe & Vane

A luxury sofa house that imports from workshops on four continents. Static site on Firebase Hosting, with the catalog, newsletter, and bag reservations in Cloud Firestore.

- Firebase project: `marlowe-and-vane` (Firestore in `nam5`)
- Live site: https://marlowe-and-vane.web.app

## Setup

```bash
git clone https://github.com/ether314/marlowe-and-vane.git
cd marlowe-and-vane
npm install
npx firebase login   # needs access to the Firebase project
cp .env.example .env # then fill in the six MV_FIREBASE_* values (the comments in the file say where to find them)
```

To run your own copy, create a Firebase project, then update `.firebaserc`, `firebase.json` (`hosting.site`), `scripts/seed-firestore.mjs` (`PROJECT`), and the values in `.env`, and deploy `firestore.rules`.

## What's here

| Path | What it is |
| --- | --- |
| `public/` | The site (no build step): `index.html`, `css/`, `js/`, `data/`, `fonts/`, `assets/` |
| `public/js/art.js`, `art-scenes.js` | Every sofa, room, scale drawing, and fabric close-up is drawn from code (SVG) |
| `public/data/catalog.json` | The catalog. Bundled fallback and the source for seeding Firestore |
| `public/data/world.json` | Dotted world map, generated by `npm run build:map` |
| `firestore.rules` | Catalog is public to read. Visitors can only append newsletter sign-ups and reservations |
| `.env.example` | The six Firebase web config variables to put in your git-ignored `.env` |
| `scripts/build-config.mjs` | Turns `.env` into `public/js/firebase-config.js` (git-ignored) |
| `scripts/seed-firestore.mjs` | Loads `catalog.json` into Firestore using your Firebase CLI login |
| `tools/dev-server.mjs` | Local preview server with the same single-page fallback as Hosting |

## Everyday commands

```bash
npm run dev              # preview at http://127.0.0.1:4174
npm run dev:csp          # same, but enforcing the production Content-Security-Policy
npm run config           # rebuild public/js/firebase-config.js from .env
npm run seed             # write catalog.json to Firestore (replaces docs with the same ID)
npm run seed -- --check  # count documents in each collection
npm run seed -- --show reservations   # read what visitors have sent
npm run deploy:hosting   # publish the site
npm run deploy           # publish the site and the Firestore rules
```

The Firebase CLI is installed in `node_modules`; sign in once with `npx firebase login`.

`npm run dev`, `npm run dev:csp`, and both deploy commands rebuild `public/js/firebase-config.js` from `.env` first, and stop with the names of any missing variables.

## Editing the catalog

Edit a piece in the Firebase console (Firestore, `pieces`) and the live site picks it up on the next page load, or edit `public/data/catalog.json` and run `npm run seed`. If Firestore can't be reached, the site falls back to the bundled `catalog.json`.

## Notes

- The Firebase web config lives in `.env`, not in the repo. That keeps it out of GitHub but does not make it secret: the deployed site serves it to every browser, because the Firebase web SDK needs it there. Access is controlled by `firestore.rules`.
- Visitors can create newsletter and reservation documents but cannot read them back. Read them with `npm run seed -- --show subscribers` or in the Firebase console.
- Spam protection beyond field validation (for example Firebase App Check) isn't set up yet.
- Checkout is not built: the bag ends in a reservation request.
- Prices, workshops, and claims in the copy are placeholders for a demonstration brand; check them before launch. Trademark searches have not been run on the name.
- Fonts (Instrument Serif, Playfair Display, Jost, Marcellus) are SIL OFL licensed and self-hosted. Map land data is Natural Earth (public domain).
